# Изменения

Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), версии — [SemVer](https://semver.org/lang/ru/). До 1.0.0 протокол SDK и API могут меняться в минорных версиях; такие изменения отмечаются здесь как несовместимые.

## [0.1.0] — 2026-11-05

Первый выпуск: весь путь от бота до дашборда, разворачивается одной командой `docker compose`.

### SDK

- **Python SDK для aiogram 3** (#2): подключается двумя строками, хендлеры бота менять не нужно.
  - события: входящие апдейты, шаги хендлеров и переходы FSM, вызовы Bot API и их ошибки, блокировки, запуски бота;
  - очередь в памяти, батчи с gzip и ретраями по `batch_id`;
  - тексты по умолчанию не собираются; есть маскирование и псевдонимизация `user_id`.
- **Go SDK** (#28): `http.RoundTripper` для любого Go-бота и адаптер `go-telegram/bot`.
  - вызовы Bot API, апдейты, время и паники хендлеров;
  - окно дедупликации `update_id`;
  - ядро без зависимостей.
- **Рассылки по сегментам** (#20): отправляет сам бот через SDK, токен остаётся у владельца.
  - лимиты Telegram и `retry_after`;
  - несколько реплик бота делят получателей.

### Приём и конвейер данных

- **collector** (#6): приём батчей.
  - ключи проектов с кэшем и singleflight;
  - дедупликация батчей и лимит проекта одним Lua-скриптом в Redis;
  - валидация по контракту `docs/contract/batch_v1.json`;
  - ответ `202` после подтверждения Kafka.
- **ch-writer** (#6): Kafka → ClickHouse пачками.
  - без дублей при падении между вставкой и коммитом смещения (план пачки в Redis и `insert_deduplication_token`);
  - DLQ для нечитаемых записей;
  - пауза чтения, пока ClickHouse недоступен.
- **Транзакции Kafka** (#33): батч пишется транзакцией с групповой фиксацией, потребители читают `read_committed`. Это закрыло дубли при остановке брокера посреди записи, которые нашли хаос-тесты.
- **Горячий путь collector** по профилю (#36): своё кодирование записей, байт в байт совпадающее с `json.Marshal`, и разбор свойств без пробных `Unmarshal`. Время на батч −29 %, аллокации −51 % (benchstat).
- **botproxy** (#14): режим прокси Bot API для ботов без SDK.
  - потоковая передача загрузок;
  - long polling и вебхуки;
  - дедупликация апдейтов, защита от SSRF.

### Аналитика и API

- **Control plane** (#4): аккаунты и вход, в том числе через Telegram; подтверждение почты и сброс пароля; проекты, участники и роли; API-ключи с отзывом; лимиты на вход и регистрацию.
- **Аналитика из ClickHouse** (#12):
  - обзор, воронки (`windowFunnel`);
  - источники с атрибуцией первого касания и стоимостью пользователя;
  - когорты удержания (`retention`);
  - ошибки, граф сценария FSM, таймлайн пользователя.
  - Запросы строятся из типизированных определений с серверными параметрами, ответы кэшируются в Redis.
- **Живая лента** (#18): события в реальном времени по SSE из Kafka.
- **OpenAPI 3** — `backend/api/openapi.yaml`.

### Антифрод и AI

- **Антифрод** (#10): доля ботоферм по источникам трафика — признаки пользователей из потока, скоринг, реферальный граф, алерты.
- **AI-модуль** (#8):
  - темы сообщений: эмбеддинги + HDBSCAN, названия от LLM или по ключевым словам;
  - алерты о росте тем;
  - вопросы на естественном языке → проверенный SQL под пользователем ClickHouse с row policy на проект;
  - объяснение аномалий.

### Дашборд

- **React + TypeScript** (#22, #24, #26): подключение бота с ожиданием первого события, обзор, живая лента, воронки, источники, удержание, граф сценария, ошибки, таймлайн, рассылки, антифрод, AI, настройки.
  - типы API генерируются из OpenAPI;
  - графики по валидированной палитре, светлая и тёмная темы, табличный вид у каждого графика.

### Надёжность и наблюдаемость

- **Prometheus и Grafana** (#30): дашборды как код, SLO с бюджетом ошибок и алертами на две скорости сгорания, правила покрыты `promtool test rules`; метрика свежести данных.
- **Хаос-тесты** (#34): под нагрузкой роняются collector, ch-writer, Kafka и ClickHouse, сеть ломается через toxiproxy; ClickHouse сверяется с журналом генератора. Все сценарии проходят, в CI — каждую ночь.
- **Сквозная трассировка OpenTelemetry** (#38): трейс батча начинается в collector, идёт в заголовках записей Kafka и заканчивается в ch-writer после коммита. Видна в Jaeger и Grafana, `trace_id` пишется в логи.
- **Генератор нагрузки** `loadgen`: трафик в формате SDK, повторы, ботофермы, тексты, журнал для сверки.
- **Тесты:** интеграционные тесты на testcontainers; e2e в CI — весь стек в docker compose, нагрузка и проверка данных, тем, антифрода и API; Playwright для дашборда.
